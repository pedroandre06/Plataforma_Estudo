===== PAGINA 5 =====
O que é SQL?
SQL (Structured Query Language) é a linguagem padrão 
para gerenciamento de bancos de dados relacionais.
Foi criada nos laboratórios da IBM na década de 1970.
É utilizada para criar estruturas, manipular dados e 
realizar consultas.
Suporta aplicações empresariais, acadêmicas, bancárias e 
muito mais.
“SQL é a linguagem que transforma dados em decisões.”

===== PAGINA 6 =====
Por que aprender SQL?
Presente em praticamente todos os SGBDs: MySQL, 
PostgreSQL, Oracle, SQL Server...
Permite definir tabelas (DDL), inserir e modificar registros 
(DML) e consultar dados (DQL).
Indispensável para analistas, cientistas de dados, DBAs e 
desenvolvedores.
Garante controle, padronização e integridade das 
informações.

===== PAGINA 10 =====
SQL: linguagem padrão para bancos relacionais
O SQL (Structured Query Language) é a linguagem 
universal para trabalhar com bancos de dados relacionais.
Desenvolvida pela IBM nos anos 1970, ela permite:
• Criar e estruturar tabelas.
• Inserir, atualizar e excluir registros.
• Consultar dados de forma eficiente.
É uma linguagem declarativa: você diz o que quer, o SGBD 
cuida do como.

===== PAGINA 11 =====
Sublinguagens SQL: o que são e para que 
servem
O SQL é composto por sublinguagens com funções distintas:
DDL – Define a estrutura do banco de dados.
DML – Manipula os dados dentro das tabelas.
SELECT – Usado para consultar dados (DQL, mas muitas 
vezes tratado como DML)
Essas sublinguagens são complementares e fundamentais 
para operar um SGBD de forma eficaz.

===== PAGINA 12 =====
DDL: Data Definition Language
A DDL permite criar e modificar a estrutura do banco:
• CREATE: cria tabelas, visões, índices.
• ALTER: altera colunas, restrições, tipos de dados.
• DROP: remove objetos do banco.
Atua sobre o esquema do banco de dados, sendo essencial na 
etapa de modelagem.
Exemplo:
CREATE TABLE alunos (
id INT PRIMARY KEY ,
nome VARCHAR(100)
);

===== PAGINA 13 =====
DML: Data Manipulation Language
A DML permite interagir com os dados armazenados nas 
tabelas:
• INSERT: insere registros.
• UPDATE: modifica dados existentes.
• DELETE: exclui dados.
• SELECT: consulta registros (embora formalmente parte 
da DQL).
Usada diariamente por aplicações para processar dados 
transacionais.
Exemplo:
UPDATE alunos SET nome = 'Carla' WHERE id = 1;

===== PAGINA 16 =====
Comandos SQL: básicos para manipular dados
 Comandos essenciais da DML para trabalhar com os 
dados em tabelas:
• SELECT: consulta registros.
• INSERT: adiciona novos dados.
• UPDATE: altera valores já existentes.
• DELETE: remove registros.
 São usados no dia a dia de sistemas para garantir que os 
dados estejam sempre atualizados e coerentes.

===== PAGINA 17 =====
Comandos intermediários: filtro, junção e 
agrupamento
O SQL também permite consultas mais elaboradas com 
comandos intermediários:
• WHERE: aplica filtros.
• ORDER BY: ordena os resultados.
• GROUP BY: agrupa registros para funções agregadas.
• HAVING: filtra grupos.
• JOIN: combina dados de várias tabelas.
 Permite recuperar informações de forma estruturada e 
analítica.

===== PAGINA 18 =====
Exemplo de consulta com SQL intermediário
Exemplo de consulta com SQL intermediário:
SELECT departamento, AVG(salario) AS media_salarial
FROM funcionarios
WHERE cargo = 'Analista'
GROUP BY departamento
HAVING AVG(salario) > 5000
ORDER BY media_salarial DESC;
 Filtro por cargo.
 Agrupamento por departamento.
 Média salarial e ordenação decrescente.

===== PAGINA 19 =====
O que é uma transação no banco de dados?
 Uma transação é um conjunto de operações que deve ser 
executado por completo ou não ser executado.
 Garante que o banco permaneça íntegro mesmo após 
falhas ou acessos simultâneos.
 Para isso, os SGBDs seguem as propriedades ACID:
• Atomicidade.
• Consistência.
• Isolamento.
• Durabilidade.

===== PAGINA 20 =====
Propriedades ACID na prática
 Exemplo: transferência entre contas bancárias – ou 
atualiza os dois saldos, ou nenhum!
Propriedade Função
Atomicidade Tudo ou nada: executa todas as operações ou desfaz 
tudo.
Consistência Garante que o banco passe de um estado válido para 
outro.
Isolamento Transações não interferem entre si.
Durabilidade Após confirmada, a transação não se perde, mesmo 
com falhas.

Reflita sobre a seguinte situação
Uma plataforma de marketplace está enfrentando sérios problemas 
com registros de pedidos e pagamentos. Após uma série de 
inconsistências, a equipe técnica identificou os seguintes sintomas:
• Pedidos duplicados ou não concluídos sendo cobrados mais de 
uma vez.
• Clientes visualizando produtos comprados por outras pessoas.
• Falhas nas transações que afetam o estoque, sem atualização 
correta.
• Relatórios de vendas com valores incoerentes entre as tabelas.
Pergunta:
Como o uso adequado de transações SQL, propriedades ACID e 
controle de concorrência pode resolver essas falhas críticas no 
sistema?

===== PAGINA 23 =====
Proposta de resolução
Por onde começar? 
Implementar controle 
transacional:
• Envolver operações 
críticas (como pedidos 
e pagamentos) em 
transações completas.
• Usar comandos 
`BEGIN`, `COMMIT` e 
`ROLLBACK` para 
garantir execução 
atômica.
• Evitar inconsistências 
com mecanismos de 
log e checkpoints no 
banco.
Aplicar corretamente as 
propriedades ACID:
• Atomicidade: a 
transação executa 
tudo ou nada.
• Consistência: mantém 
o banco em estado 
válido antes e depois.
• Isolamento: impede 
que transações 
simultâneas interfiram 
entre si.
• Durabilidade: garante 
que os dados 
persistam após falhas.
Estabelecer controle de 
concorrência:
• Utilizar bloqueios 
(locks) para evitar 
conflitos de escrita.
• Aplicar controle por 
timestamp em 
sistemas com alta 
concorrência.
• Evitar anomalias 
como leituras sujas e 
atualizações perdidas.
