===== PAGINA 5 =====
O que são Bancos de Dados?
Conceito-chave:
Um banco de dados é uma coleção estruturada de dados 
relacionados, projetada para ser acessada de forma eficiente 
por múltiplos usuários e aplicações.
Importância prática:
• Utilizados em praticamente todos os sistemas digitais 
atuais.
• Presentes em serviços bancários, e-commerce, hospitais, 
universidades e redes sociais.
Você sabia?
Bancos de dados relacionais são os mais utilizados no mundo 
corporativo por garantirem organização, integridade e rapidez 
na manipulação de dados (Elmasri; Navathe, 2018).

===== PAGINA 6 =====
Por que Modelar Dados?
Objetivo da modelagem:
Traduzir as regras e necessidades de um sistema real em uma 
estrutura lógica que possa ser implementada em um banco de 
dados.
Benefícios da modelagem:
• Redução de redundância.
• Clareza na estrutura dos dados.
• Suporte à integridade e à escalabilidade.
Ferramenta principal:
Modelo Entidade-Relacionamento (MER) – permite 
representar graficamente entidades, atributos e 
relacionamentos (modelo proposto por Peter Chen em 1976).

===== PAGINA 7 =====
O Modelo Relacional
Definição:
É o modelo mais adotado para representar dados em forma 
de tabelas, onde:
• Linhas = registros (tuplas)
• Colunas = atributos
Chaves e integridade:
• Chave primária: identifica unicamente cada registro.
• Chave estrangeira: estabelece relações entre tabelas.
Baseado em:
Teoria dos conjuntos e lógica de predicados (modelo 
relacional apresentado por Edgar Codd em 1970).

===== PAGINA 8 =====
SGBDs e a Estrutura Relacional
SGBD (Sistema Gerenciador de Banco de Dados):
Software que permite criar, manipular e consultar dados 
armazenados em bancos relacionais.
Principais funções:
• Definição de esquemas.
• Manipulação de dados (CRUD).
• Garantia de integridade e controle de concorrência.
Exemplos:
MySQL, PostgreSQL, SQL Server, Oracle Database.
Curiosidade:
Esses sistemas utilizam a linguagem SQL para interagir com os 
dados.

===== PAGINA 10 =====
O que é o Modelo Entidade-Relacionamento 
(MER)?
Definição:
O MER, proposto por Peter Chen em 1976, é uma técnica de 
modelagem conceitual que permite representar graficamente 
os elementos e os relacionamentos de um sistema real.
Para que serve?
• Facilita o entendimento do domínio de dados.
• Serve como ponte entre usuários e desenvolvedores.
• Prepara a base para o modelo relacional.
Pensar visualmente = projetar melhor!

===== PAGINA 11 =====
Principais Componentes do MER
Entidades:
Representam objetos concretos ou conceituais (ex.: cliente, 
produto, pedido).
Atributos:
Propriedades das entidades (ex.: nome, CPF, data de 
nascimento).
Tipos: simples, compostos e multivalorados.
Relacionamentos:
Indicam como as entidades estão conectadas.
Exemplos: “Cliente realiza Pedido”, “Aluno cursa Disciplina”.

===== PAGINA 12 =====
Cardinalidade e Participação
Cardinalidade:
Define o número de ocorrências permitidas entre entidades:
• 1:1 (um para um).
• 1:N (um para muitos).
• N:M (muitos para muitos).
Participação:
• Total: todos os registros participam do relacionamento.
• Parcial: a participação é opcional.
Essencial para prever integridade referencial!

===== PAGINA 14 =====
Do MER ao Modelo Relacional
 Transformação prática:
Cada entidade vira uma tabela.
Cada relacionamento vira:
• Uma chave estrangeira (1:N)
• Uma nova tabela (N:M)
 Exemplo:
Entidade Aluno + Entidade Disciplina + Relacionamento Matrícula
→ Gera uma tabela MATRÍCULA com atributos próprios (data, nota)
 Frase de impacto:
“O MER é o mapa. O modelo relacional é a estrada.” – adaptado de 
Heuser (2009)

===== PAGINA 16 =====
O que é o Modelo Relacional?
 Conceito-chave:
O modelo relacional representa dados por meio de tabelas 
(ou relações), onde:
• Cada linha = tupla (registro)
• Cada coluna = atributo (característica)
 Fundamentação teórica:
Baseado em teoria dos conjuntos e lógica de predicados de 
primeira ordem (Codd, 1970).
 Objetivo:
Organizar dados de forma estruturada, permitindo 
flexibilidade, integridade e desempenho nas consultas.

===== PAGINA 17 =====
Estrutura de uma Tabela Relacional
 Componentes essenciais:
• Atributos (colunas): representam os dados de cada 
entidade.
• Tuplas (linhas): representam registros únicos.
• Domínio: define o tipo de dado aceito em um atributo (ex.: 
inteiro, data, texto).
 Importante: cada tabela deve ter pelo menos uma chave 
primária para garantir integridade de entidade.

===== PAGINA 18 =====
Chaves em Tabelas Relacionais
 Chave Primária (PK):
Identifica unicamente cada registro. Não aceita valores nulos 
nem repetidos.
 Chave Estrangeira (FK):
Estabelece vínculo entre tabelas. Deve referenciar uma chave 
primária válida de outra tabela.
 Exemplo:
Tabela Pedido com id_cliente como chave estrangeira 
referenciando Cliente(id_cliente).

===== PAGINA 19 =====
Integridade em Bancos Relacionais
 Integridade de Entidade:
Toda tabela deve ter uma chave primária.
 Integridade Referencial:
Garante que os relacionamentos entre tabelas sejam válidos.
 Integridade de Domínio:
Cada valor precisa respeitar o tipo e as restrições definidas 
(ex.: CPF com 11 dígitos).
 Implementadas via constraints:
PRIMARY KEY , FOREIGN KEY , NOT NULL, CHECK, UNIQUE.

===== PAGINA 20 =====
Exemplo Prático + SQL
 Tabelas: Cliente e Pedido
CREATE TABLE Cliente (
  id_cliente INT PRIMARY KEY,
  nome VARCHAR(100) NOT NULL,
  cpf CHAR(11) UNIQUE
);
CREATE TABLE Pedido (
  id_pedido INT PRIMARY KEY,
  data DATE,
  id_cliente INT,
  FOREIGN KEY (id_cliente) REFERENCES Cliente(id_cliente)
);
 Explicando:
O id_cliente é a chave primária da tabela Cliente e chave estrangeira em Pedido.

===== PAGINA 22 =====
Reflita sobre a seguinte situação
Uma instituição de ensino está desenvolvendo um novo sistema 
acadêmico para gerenciar alunos, cursos, professores e matrículas. 
Após uma primeira versão do banco de dados, surgiram os 
seguintes problemas:
• Informações duplicadas de alunos aparecendo em diferentes 
disciplinas.
• Dificuldade em gerar relatórios por falta de padronização nos 
dados.
• Relacionamentos entre entidades gerando erros por ausência de 
vínculo entre tabelas.
Pergunta:
Como o uso de chaves primárias, chaves estrangeiras e a 
integridade referencial podem ajudar a resolver esses problemas?

para acelerar buscas
